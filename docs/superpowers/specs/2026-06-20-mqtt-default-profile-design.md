# MQTT 默认测试配置设计

## 目标

让云聚通 Probe App 在首次安装或从旧测试包覆盖升级后的第一次启动时，直接显示已确认的中国测试环境 MQTT 参数。后续启动继续使用用户在 App 内保存的参数，不重复覆盖。

## 默认配置

App 使用发送端身份连接 MQTT：

- Protocol：`MQTT`
- Host：`192.168.8.135`
- Port：`1883`
- Env：`test`
- ClientId：`V37G00000108`
- PubTopic：`V37C00000133`
- SubTopic：`V37G00000108`
- SN Pwd：`111159`
- WLAN MAC：`98:26:ad:23:28:2b`
- Username：由 `test` 环境自动推导
- Password/token：保持为空，运行测试时用发送端 SN、密码和 MAC 自动获取

接收端 `V37C00000133` 的 IP `192.168.8.178`、密码 `253602` 和 MAC `00:03:7f:12:34:56` 属于 MQTT Echo 服务配置。当前 App 不使用接收端凭据进行认证，因此不新增不可用的 UI 字段，也不把这些凭据写入 App 的发送端配置。

## 配置迁移

新增一个默认配置版本号。App 加载设置时：

1. 如果设备没有当前版本标记，执行一次迁移，把协议和上述 MQTT 字段写入 `SharedPreferences`。
2. 保留 Count、PPS、Bytes、Timeout、测试标签等非 MQTT 参数。
3. 写入当前默认配置版本号，确保迁移只执行一次。
4. 后续启动读取已保存配置，允许用户修改并保存，不再自动重置。

这既覆盖全新安装，也解决旧测试包覆盖安装后仍显示旧协议或空 MQTT 字段的问题。

## 代码结构

新增一个不依赖 Android UI 的默认配置类，集中保存字段值、协议索引和迁移版本。`MainActivity` 只负责在加载配置前检查版本并把默认配置写入偏好设置，避免默认值继续散落在 Activity 中。

不修改 MQTT 连接、Token 获取、探测和导出逻辑。

## 测试与验收

- 先写单元测试，验证默认协议为 MQTT、全部发送端字段映射正确，以及旧版本需要迁移、当前版本不重复迁移。
- 运行单元测试和 `assembleDebug`。
- 检查 APK 包名、版本、最低 Android 版本和签名。
- 新 APK 覆盖安装后首次启动应显示本设计中的 MQTT 参数；再次修改并重启时应保留用户修改值。
