# Android Probe App 三页流程 UI 设计

## 目标

将 `android-probe-app` 的操作流程收敛为严格的三步线性流程：参数设置、运行状态、测试结果。用户不能通过标签任意跳页；页面只由明确操作或测试状态推进。

本次只调整 Android App 的界面、导航和交互状态，不改变 UDP、TCP、MQTT 探测算法、指标口径和文件格式。

## 页面架构

继续使用单个 `MainActivity`，保留三组独立页面容器，并增加明确的页面状态：

- `CONFIG`：参数设置页
- `RUNNING`：运行状态页
- `RESULT`：测试结果页

页面切换集中由一个状态切换方法管理，业务回调不直接操作多个页面的可见性。移除当前可点击的顶部标签，替换为不可点击的三步流程提示。这样既保留当前纯 Java View 架构，也避免跨 Activity 传递运行任务、图表样本和错误信息。

## 页面与操作

### 1. 参数设置页

- 顶部显示应用名称、当前步骤“1 参数设置”和简短说明。
- 参数按测试模式、网络目标、探测参数分组。
- 选择 MQTT 时展开 MQTT 参数区；其他协议隐藏该区。
- 页面底部提供明确的主操作“开始测试”。
- 点击开始后先校验所有可见参数。校验成功时保存参数、初始化本次运行状态并进入运行页；校验失败时留在本页，显示具体错误并将焦点移动到首个错误字段。
- 从结果页点击“再次测试”返回时保留上次参数，但清除上次运行的瞬时状态和错误提示。

### 2. 运行状态页

- 顶部显示当前步骤“2 运行状态”、协议、目标地址、模式标签和运行状态。
- 重点展示进度、已发送/已接收、丢包率、P95、P99、平均 RTT、Jitter 和最大连续丢包。
- RTT 趋势图和丢包事件条保留，并延续现有节流刷新，避免主线程频繁重绘。
- 页面底部提供危险操作“停止测试”。点击后弹出确认框，避免误触。
- 系统返回键和页面返回操作在运行中采用同一确认框：
  - “继续测试”：关闭弹窗，任务继续。
  - “停止并查看结果”：停止任务，以已有样本生成结果并进入结果页。
- 运行期间不可进入参数页，也不可提前打开结果页。

### 3. 测试结果页

- 顶部显示当前步骤“3 测试结果”和本次运行的最终状态。
- 首屏优先展示结论状态和关键指标，再展示完整汇总、与上次有效测试的对比、导出状态及文件路径。
- 正常完成、手动停止和返回确认停止均进入本页，并明确区分“已完成”和“已停止”。
- 连接失败、鉴权失败或未发出任何探测包也进入本页，显示“测试失败”、可读原因和建议操作，不把零值指标表现为有效结果。
- 底部提供“再次测试”和“导出结果”。再次测试回到参数页并保留参数。
- 结果页按系统返回键回到参数页，不回到已经结束的运行页。

## 状态与数据流

一次测试使用统一的运行结束入口，接收结束类型、错误信息、最终指标和样本：

- `COMPLETED`：达到预设数量，正常完成。
- `STOPPED`：用户点击停止或确认返回。
- `FAILED`：初始化、连接、鉴权、发送或运行过程失败。

该入口负责防重复执行、停止 Runner、冻结最终数据、更新结果页、恢复按钮状态、按策略导出并切换到结果页。正常完成回调、停止按钮和返回确认不得各自复制结束逻辑。

测试开始后生成本次会话标识。来自旧会话或已经结束会话的异步回调必须忽略，避免停止后仍刷新图表或覆盖结果。页面状态和 Runner 状态分开记录，确保旋转被锁定的横屏环境中仍不会因重复点击产生两个任务。

## 异常处理与友好反馈

### 参数与启动

- Host 不能为空；Port 范围为 1–65535；Count、PPS、Bytes、Timeout 必须为合理正数。
- MQTT 必填项根据“手动 Token”或“自动取 Token”方式分别校验，错误信息使用用户可理解的字段名称。
- “开始测试”在校验和初始化期间禁用并显示处理中状态，防止连续点击启动多个任务。
- 参数错误使用字段级提示和页面级短提示，不只显示笼统 Toast。

### 运行过程

- 将“正在连接”“正在鉴权”“探测中”“正在停止”作为可见状态，不让界面看起来卡住。
- Stop 操作进入“正在停止”后禁用，结束流程具备幂等保护。
- 连接超时、DNS 失败、连接拒绝、MQTT 鉴权失败、Token 获取失败、网络断开和未知异常显示不同的简明原因；技术细节可附在次级文本中。
- 若已有样本，失败结果仍展示已采集指标，同时标明结果不完整；若没有样本，不计算改善率，也不写入有效对比基准。
- 图表无样本时显示空状态说明，而不是空白区域。

### 导出

- 自动导出失败不阻止进入结果页。
- 结果页显示导出成功路径或失败原因，并提供“重试导出”。
- 没有可导出的样本时禁用导出按钮，并解释原因。

### 导航与生命周期

- 参数页按系统返回键正常退出 App。
- 运行页按系统返回键必须二次确认。
- 结果页按系统返回键回到参数页并保留参数。
- App 销毁时停止 Runner；已经进入结束流程的回调不得再次切页或弹出提示。

## 视觉与可用性

- 保持现有浅色、数据工具型风格，使用统一的颜色、圆角和 4/8dp 间距节奏。
- 三步提示只用于说明流程，当前步骤高亮，完成步骤使用完成态，不具备点击效果。
- 主按钮和危险按钮使用文字明确表达结果，不仅依赖颜色和图标。
- 所有按钮保证至少 48dp 高度，提供按压、禁用和加载反馈。
- 指标颜色同时配合标签或状态文字，避免仅靠红绿区分。
- 弹窗标题、说明和按钮使用动作结果文案，例如“停止并查看结果”，避免模糊的“确定/取消”。
- 继续支持固定横屏，小屏内容可滚动，底部操作区不得遮挡内容。
- 不使用 Emoji 作为结构图标；如保留图标，统一采用 Android 矢量资源。

## 测试范围

### 单元与状态测试

- 验证三页状态只能按允许的方向切换。
- 验证重复开始、重复停止和迟到回调不会创建第二个任务或覆盖结果。
- 验证 `COMPLETED`、`STOPPED`、`FAILED` 三种结束状态的结果文案和数据规则。
- 验证无样本失败不会进入有效对比基准，部分样本失败会保留不完整指标。
- 验证各协议参数校验，尤其是 MQTT 自动 Token 与手动 Token 分支。

### 交互验证

- 从参数页开始测试后只能进入运行页。
- 运行中返回或点击停止会弹出确认，取消后任务继续，确认后进入结果页。
- 正常结束自动进入结果页。
- 再次测试和结果页返回均回到参数页并保留参数。
- 导出成功、失败、重试和无样本禁用状态均有明确反馈。
- 在横屏小尺寸设备上验证滚动、固定操作区、弹窗和软键盘不会遮挡关键控件。

## 非目标

- 不引入 Fragment、Navigation Component、Compose 或新的跨页面架构。
- 不调整探测协议、统计公式、服务端 Sidecar 或数据导出格式。
- 不在本次实现历史结果列表或独立报告管理功能。
